# V4 計画・仕様

## 目的と優先順
V3を基準に、ゲストの入口、サーバー確定戦績、カスタムの拡張、終了後チャットを追加する。既存差分なし。V3 source: 8c6c6b5f703c1295046e3bc8d5c39c562b5f166e / release/v0.3.0。Sitesの復旧先はRELEASE-V3.json。

1. ゲストは暗号学的乱数のHttpOnly Cookie、DBにはハッシュのみ。アカウントは既存の仮名キー。メール・本名を保存/表示しない。ゲスト期限30日、同じブラウザ限定。ログイン後の明示操作で戦績を連携し、連携後のゲストCookieは無効化する。
2. 対戦確定と結果保存を同一トランザクションで行う。再送/再接続/競合で二重計上しない。試合数/勝敗/勝率/人数別/履歴/途中退出を表示。終了時の最終接続確認が2分より古い参加者を途中退出扱い（途中退出は敗北）。試合中の部屋閉鎖/期限切れは中止で集計しない。ゲスト戦績もDBに保存、公式ランキングはログイン参加の標準戦のみ。ゲスト引継ぎは個人戦績には含めるがランキングには遡及加算しない。月間は日本時間。
3. 標準はV3の配役/枚数を維持。カスタムは定員3〜10、豚男1〜定員-1、罠1〜5。開始時の実人数で陣営と特殊役職の枠を再検証。おすすめ設定は6人/豚男2/罠2/鑑定士1/飼育係1。
4. 鑑定士（探検家）は試合中1回、他者の未公開カード1枚を本人だけが確認。調査先・結果・使用通知は公開しない。古参の飼育係（探検家）は開始時に他者1名の陣営を本人だけが知る。調査役は5人以上専用で、能力は各最大1名。少人数で情報が強すぎるため3〜4人では選択不可。おすすめは試遊用であり、勝率の均衡を保証する設定ではない。誰でも会話で役職を名乗れる。護衛・陣営変化・即敗北能力はタイミング/複雑さのため今回採用しない。
5. 郵便局員・手紙・第三陣営はV5以降へ延期。ユーザーから人数ごとのバランス検証が必要との指摘を受け、4枚/3枚という未検証の仮案は採用しない。実装からも除外。人数別シミュレーションと人間の対戦で検証するまで公開しない。
6. 終了後もチャットを保存。再戦/待機室へ戻すとクリア。

## ロールバック境界
V3保存版とタグを保持。新テーブルの追加のみで既存テーブルを破壊しない。V3は新テーブルを参照しないため戦績データは保持される。ただしV3はゲスト認証・特殊役職を解釈できない。ロールバック時はV4の試合を終了させ、カスタム/ゲストの部屋をバックアップして閉鎖してからV3を再公開する必要がある。未完了カスタム戦のV3継続は推奨しない。本番で復旧試験やデータ削除は実施しない。

## 検証計画
標準回帰、特殊役職の権限/非公開投影/回数、設定境界、Cookie推測/期限/連携、結果の競合/再送/集計、チャット寿命、型チェック、ビルド、ローカルブラウザ。公開後は読み取りとゲスト入口確認を行う。

## 検証経過

25テストPASS、標準800対戦＋カスタム40設定の完走・カード保存則・権限・非公開情報を検証。型チェックPASS。V3互換性は標準戦182状態で確認（カスタム/ゲストは対象外）。ローカルHTTPで6ゲストのカスタム戦16手完走、秘密鑑定、終了後チャット、戦績保存、ChatGPT相当の開発認証への引継ぎ、旧ゲストCookie失効、CSRF拒否を確認。本番への試験対戦書込なし。ブラウザでゲスト入口、カスタムおすすめ部屋作成、再読込で席復帰、戦績画面を確認。

調査役を含む人間同士の勝率・発言によるバランス、実機スマホ、実アカウント間の引継ぎは未検証。自動テストの完走はバランスの証明ではない。V3以前から進行中の試合はmatchIdを持たないため戦績を遡及生成しない。
