# リノベーション記録（2026-11-03）

## 目的と安全境界

Sitesで公開し、ChatGPTアカウントで友人が参加でき、QRから開けるゲーム環境を優先する。ユーザーが公開範囲を「URLを知っている人」と指定。新しいSiteと専用D1だけを使用。元のGitHub main・Render・既存DBは変更しない。認証メール・プロフィール名・認証トークンは保存/ログ出力せず、Site内のユーザーIDをハッシュ化した識別子と任意のゲーム表示名を使用する。表示名・チャットに個人情報を入力しないよう案内する。

## 確認した不具合

1. `legacy/server/handlers/connection-handlers.js` の接続コールバックが `setupRoomHandlers(io, socket, ...)` を呼ぶ一方、`room-handlers.js` は `setupRoomHandlers(io)` 内でさらに `io.on('connection')` を追加する。最初の接続には部屋ハンドラーがなく、後の接続では累積したハンドラーが重複する。
2. ソケットIDをプレイヤーIDに使用し、再接続を同じ席へ復元する契約がない。全員切断時に部屋を削除する。
3. ラウンド完了後の3秒タイマー中もカード操作を受け付け、複数の次ラウンド処理を予約できる。
4. 状態全体を `gameUpdate` と `gameStarted` で送信し、他人の未公開手札・役職をクライアントが取得できる。
5. 部屋一覧がプレイヤー名を `innerHTML` に挿入する箇所がある。新UIはReactのテキスト描画のみを使用。
6. 旧テストにpackage.json/YAML等の設定例が混在し、参照する `server/gameLogic` も存在しない。旧テストのpassは主張しない。

## 採用した設計

- **ルール維持**：鍵の所有者が他人のカードを1枚開く。全員の同時カード選択ではない。人数別カード枚数・陣営配分・勝利条件は元コードから移植。
- **一つの保存状態**：部屋ごとのJSONをD1に保存。接続の寿命と席の寿命を分離。部屋内には接続中人数によるカード再配布条件を持たせない。
- **原子的な操作**：`UPDATE ... WHERE version = expectedVersion`。1件だけ成功。後続は409で再取得。タイマーを使わず、1操作内でカード公開・勝敗・再配布まで計算して確定。
- **重複作成防止**：作成者キーのDB一意制約で、二重クリック・並列タブ・通信再送も同じ部屋に収束。
- **再送**：操作IDを直近80件保存。競合時には自動でカードを再選択せず、最新盤面を表示。
- **カード保存則**：公開済みカードだけ除外し、未公開の実カードIDを維持して再配布。カードIDは乱数UUIDで種類を推測できない。
- **情報分離**：本人の手札・役職と公開済み情報だけをallowlistで返す。観戦者は同じバージョンの公開射影を取得。認証キー・合言葉ハッシュ・再送記録は返さない。
- **参加保護**：合言葉はPBKDF2(SHA-256, 100000回, 部屋固有salt)。ログイン・同一Origin・JSON・サイズ・表示名・人数・操作権限をサーバーで検証。更新系は1アカウント60回/分。
- **軽い同期**：2秒間隔（ロビー5秒）で取得し、非表示時は止める。永続WebSocket接続、Redis、専用サーバー運用は不要。高速アクションゲーム向けの通信設計ではない。

## 検証の意味

- Nodeテスト12件：3〜10人×100シードの計800ゲーム、終局、カード保存、ラウンド遷移、役職人数、再接続射影、不正操作・入力、重複名、チャット長、再戦、ホスト引継ぎ。
- Miniflareの実D1テスト：8並列作成が1部屋、並列参加、カード同時操作は1成功、開始再送、合言葉、観戦非漏洩、書込制限、期限切れ、閉鎖。
- QRはqrcodeで生成し、独立したjsQRデコーダーでURL一致を検証。
- ブラウザQA・型検査・ビルド・公開の結果は公開時の検証記録を参照。ローカルのモック認証と本番の複数ChatGPTアカウントは区別する。

## 残る制約と推奨

- 不在プレイヤーに自動で代打をさせない。手札と勝敗の整合性を優先し、復帰を待つ。復帰不能ならホストが部屋を閉じて再作成する。
- 全員がタブを閉じても部屋を残すため、席表示はオンライン状態を意味しない。
- ルーム一覧は更新順で最大100件。招待コードは直接アクセス可能。大規模運用時はページング・DB負荷・悪用耐性を計測してから拡張する。
- 2秒同期なので、相手の操作が見えるまで待ち時間がある。低遅延化は実際の体験と負荷を測定して決める。
- E2Eの次の重点は、実アカウント3人以上による初回ログイン、スマホでの復帰、1試合完了、観戦を含む受け入れ。
- ランキングやリプレイの追加、複雑な自動代打、別のリアルタイム基盤への再移行は、受け入れ前には推奨しない。

## ローカル環境で発生した検証障害

Documents配下の依存ファイルにmacOSの `compressed,dataless` 属性が付き、一部のNode読み込みが空として扱われる事象を確認。アプリのルールテストは通過したが、D1シミュレータの起動が失敗した。ロックファイルを変更せず、依存関係をクラウド同期外の `~/.codex/cache/pig-house-deps-1103/node_modules` に再インストールし、作業コピーからGit管理対象外のシンボリックリンクで参照。以後12テストは通過。このローカルリンクやキャッシュは公開物にもGitにも含めない。
