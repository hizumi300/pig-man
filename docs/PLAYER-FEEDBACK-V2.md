# プレイヤーフィードバック改修計画 — v0.2.0 / Sites Version 2予定

作成日: 2026-11-04。実装前に作成し、配役回答と検証結果を追記。

## 目的・現行版の根拠

部屋 C2ABFD1D で3人オンライン対戦が問題なく動作したとユーザーから報告された。この実プレイの成果を維持し、秘密情報の扱い、ラウンドの視認性、チャット、スマートフォンでの操作性を改善する。報告から再接続・全人数・耐久試験の成功までは推定しない。

Sites Version 1 / package 0.1.0 / Git `cc329f2dd7167ed53b8ea1a66e1cc60112b26ff6` が基準。Sitesに保存済みのアーカイブと成功したデプロイを確認した。Gitタグ `release/v1-online-verified-2026-11-04` を保存し、改修は `codex/player-feedback-v2` で行う。復旧情報は [ROLLBACK-V1.json](ROLLBACK-V1.json)。

## 改修順序と受け入れ条件

|順序|対象|変更方針・受け入れ条件|
|---|---|---|
|1|自分を含む手札の秘匿|未公開カードは全員分を裏向きにする。APIも本人へ位置別の種類を送らない。本人だけに未公開の子豚・罠・空き部屋の枚数を別途返す。相手や観戦者には内訳を返さない。公開済みカードだけ表にする。|
|1|表示切替|手札・役職の「隠す/表示」ボタンを撤去。自分の役職は常時表示。他人の役職はゲーム中引き続き非公開。|
|2|カード演出|新たに公開されたカードに短い反転アニメーション。ポーリングの重複、再描画で再生し直さない。動きを減らす設定に対応。|
|2|ラウンド遷移|最後の公開カードを約2〜3秒確認でき、その後にラウンド表示を演出する。閉じる操作が必要なダイアログは使わない。勝敗確定時も最後のカードを確認できる。サーバーでも待機中の次手を拒否し、連打・複数端末・再接続で二重進行しない。|
|3|チャット追従|新しい投稿が届いたとき、チャット枠内だけを最新位置まで移動。新着がないポーリングでは読んでいる過去ログを動かさない。送信・他者の投稿・ラウンド区切りを検証。|
|3|チャットの区切りと保存|ゲーム番号とラウンドを各投稿に付与し、ラウンド見出しを表示。同じゲームの過去ラウンドを振り返れる。履歴上限は明記してメモリ・転送量を制限。既存投稿のラウンドを推測しない。|
|3|ゲーム終了時のチャット|勝敗確定時にそれまでのチャットを消去。再戦・待機室へ戻る際も前ゲームの会話を引き継がない。部屋閉鎖では部屋ごと消去。「ゲームが割れたら」は終了・再戦・閉鎖の意味として扱う。|
|4|スマホとチャット領域|カード幅に上限を設け、5枚→2枚でも拡大しない。裏向きカードのタップ領域は確保。チャットを現在の200pxより縦長にし、320/390/768/1280pxで横溢れと到達しやすさを確認。|
|5|豚男の人数説明|ルール説明と待機室に、人数別の可能な豚男人数を表示する。表示と配役処理は単一の規則を参照。実人数の公開は別の判断とし、ゲーム中に秘密の配役を漏らさない。下記の確定規則を採用。|
|6|6時間で部屋失効|最終の成功した利用者操作から6時間。閲覧・自動ポーリング・失敗した操作・重複リクエスト再送では延長しない。期限到達後は一覧・直接URL・APIとも利用不可。既存部屋も最終操作時刻で判定する。不要な常駐タイマーは導入しない。|

## 実装とロールバックの方針

- `lib/game.ts`: 秘匿用レスポンス、本人用枚数、公開演出の情報、チャットのラウンドと寿命。内部カードの保存則を維持し、過去の公開IDから新しい位置を追跡できないようにする。
- `lib/room-store.ts`: 6時間の判定、競合制御、次手の待機時間。DBのテーブルを作り直さず、適用済みマイグレーションを変更しない。
- `app/game-client.tsx` / `app/globals.css`: 演出・チャット・スマートフォン表示・役職人数説明。
- `tests/` / `scripts/qa-http.mjs`: 新仕様の境界検証と既存の対戦回帰検証。`README.md` 等とバージョン表示も更新。

次ラウンドの状態は原子的に確定し、直前の公開盤面とサーバー時刻による3秒の操作待機を追加した。旧版が理解できない新しいゲーム状態への置換や、プロセス内タイマーに依存した再配布は避ける。クライアントは最後の公開盤面を最低2秒表示する。旧版で読める状態を維持する。

期限切れの利用停止とDB行の物理削除時刻は区別する。6時間経過で利用停止し、行は後続リクエスト時の掃除で削除する。アクセスがない時間にも6時間ちょうどの物理削除を保証するには別の定期実行が必要で、この版では追加しない。

## 復旧手順と限界

重大な進行不能・秘密情報の漏れ・保存破損が見つかった場合は、新しいデプロイ結果を記録し、Sitesで `ROLLBACK-V1.json` の `version_id` を同じ `project_id` に再デプロイする。古いブランチを再ビルドせず、保存済みアーカイブを使用する。成功状態とURLを確認する。

Gitの作業を戻す必要がある場合も現行ブランチを強制リセットせず、タグから復旧ブランチを作る。既存差分は保持する。公開DBの書き換えや実プレイヤーを使ったテストは行わない。

コードのロールバックでは削除済みチャット・期限切れで削除した部屋は復元できない。また、旧版へ戻ると手札の位置が本人に見える旧仕様・7日保存の旧処理も戻る。削除前データの個人情報を含むバックアップは作成しない。現在の認証・公開範囲・QRの宛先は維持する。

大規模な再設計、通信方式の再移行、未確認の役職確率の採用、検証のためだけの本番ロールバックは推奨しない。
